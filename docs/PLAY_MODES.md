# Play Modes

These are host-level interaction patterns.

They are deliberately abstract: the repository does not prescribe concrete scenarios.

## Single Lens

Hold one Lens stable across a conversation.

Use when the goal is depth and continuity.

## Lens Swap

Keep the analytical object fixed and switch the Lens.

Use when the goal is to experience how problem framing changes.

## Blind Draw

Select a Lens without revealing its name until after the first analysis.

Use when the goal is to reduce label-driven expectations.

## Lens Stack

Combine two explicitly compatible lenses.

Use cautiously: stacking can blur distinctiveness.

## Contrast Mode

Run two lenses independently, then compare:
- what each noticed first;
- how each framed the problem;
- where causal explanations diverged.

## Lens Forge

Provide a source set and distill a new Lens.

This is the main creation workflow.

## Book Lens

Freeze the source scope to one book.

Useful when a thinker-level Lens would be too broad.

## Thinker Lens

Distill a documented real thinker from sufficient primary material.

## School Lens

Distill:
- shared core;
- internal branches;
- disputes;
- historical shifts.

## Personal Lens — Experimental

Distill a recurring reasoning pattern from sufficient user-supplied material.

This should model:
- attention;
- questions;
- causal habits;
- evidence preferences;

not merely writing style or personality.

## Interface principle

Play modes should live in the Host / Orchestrator layer.

Individual Lens files should remain clean and composable.
